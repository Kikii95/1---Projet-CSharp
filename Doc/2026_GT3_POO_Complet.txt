--- Qu’est-ce qu’un objet ? ---


Un ensemble de champs et de méthodes
Le but : rassembler un ensemble cohérent de fonctionnalités.
-Organisation sous forme d’objet, on fait en sorte de ne lui dédier qu’une
responsabilité .
-Sur Unity (ou autre moteur) on travaille majoritairement en composition  et
moins en héritage
-Chaque classe a sa responsabilité et c’est l’ensemble des composants qui va donner
une cohérence à une entité (joueur, PNJ, interactable etc)



--- Une fois l’ensemble des composants mis en place : ---

-On doit gérer la communication entre chaque composants, on parle alors
d’architecture , les composants ont des relations entre eux.
-Ils peuvent se donner de l’information (property)
-Ils peuvent s’avertir d’un évènement (event)
-Ils peuvent utiliser une fonctionnalité d’un autre composant (method)
-Un composant conserve également des informations précieusement (ﬁeld)

Quelques bases

Classe

Concept
Rassemble un ensemble d’information et de fonctionnalité
Une classe est un plan de construction, on écrit le contenu que va contenir chaque
instance. Une instance  est unique et peut évoluer indépendamment.
Type = Classe = Plan de construction
Instance = this = Composant évoluant au runtime


Concept
Les instances possèdent donc les mêmes champs et méthodes mais leur
contenu change de façon indépendante (pour conserver une information au
niveau du type, on utilisera static)


Visibilité
Dans une classe, les champs et méthodes ont 2 visibilités principales (+2
bonus).
Permet d’ouvrir nos fonctionnalités aux autres composants (ou à l’inverse,
permet de cacher nos mécanismes qui ne concernent que nous)
L’idée n’est de proposer aux autres classes que le stricte minimum. On propose
une surface d’appel qui respecte les besoins des autres composants, le reste
c’est notre mécanique interne.

Visibilité (bonus)
public : dispo à tous
private : dispo uniquement pour notre classe
protected : héritage
internal : assembly

Champs

[T ype] label;
int : nombre entier
ﬂoat : nombre à virgule ﬂottante (ajouter le ‘f’)
string : chaine de caractère
bool : vrai/faux (true/false)
Vector3 : position ou direction (Unity)
Color : couleur (Unity)
ex : int _maVie;       ﬂoat _monArgent;         string _monNom;            Vector3 _maDirection;
Version complète : [Attributs] [Visibilité] [Type] label;

L’information
Nos champs nous permettent de conserver des informations qui doivent rester dans le
temps.
Convention de nommage :  commencer par un ‘_’ puis camelCase
Ex : _currentLife, _maxLife
/!\ Attention : une variable n’est pas un champs (dispo qu’au sein d’une fonction)

Pas de champs public !
-On dévoile toutes nos informations vitales
-On autorise d’autres composants à modiﬁer nos valeurs essentielles
-Une vie à -12 ? Merci notre cher.e stagiaire
-Une vie supérieure à notre valeur de vie max ? Oups
-Nos champs, c’est notre jardin secret
-Il n’y a QUE notre composant qui doit y avoir accès.
-… Et si on veut proposer aux gens d’accéder à ces valeurs, on mettra en place des
propriétés
-On peut choisir si on veut proposer ou pas la conﬁguration des valeurs initiales
via l’editeur. [SerializeField]

Sur Unity
[SerializeField] permet au game designer de renseigner une valeur de départ pour le
composant … Mais il peut faire des erreurs ou il peut avoir la ﬂemme de renseigner des
valeurs initiales
On peut mettre une information sur un champs, une méthode ou une classe via
l’utilisation d’un attribut.  Il existe tout un lot d’attribut déjà existant et on peut
également créer les nôtres au besoin (un peu plus avancé).

Méthodes

Concept
Rassemble une série d’instructions formant une fonctionnalité.
Variables, assignations, conditions, boucles, appels de fonction
Une méthode peut être enclenché par un autre composant (fonction publique)
Une méthode peut également être dispo que pour notre fonctionnement interne
(fonction privé)

2 catégories de méthodes


--- -Fonction : ---

-Ensemble d’instruction aboutissant à un résultat donné.
-ex : Mathf.Abs, Mathf.Min etc


--- -Procédure : ---

-Ensemble d’instruction ne retournant pas de résultat
-ex : Debug.Log

V ariable

[TYPE] labelDeLaV ariable = {V aleur initiale};
-Une information temporaire au sein d’une fonction/méthode
-camelCase simple
Faisons la distinction entre champs et variable
-un champs commence par un ‘_’ (underscore) et est écrit en camelCase
-_monChamps
-une variable est écrit en camelCase
-maVariable
Quand on modiﬁe une information labélisé avec un underscore on sait qu’on touche à
un champs

Scope
Une variable n’est disponible qu’au sein d’une fonction. À la ﬁn de l’execution de la
fonction la variable n’existe plus.
Elle n’existe que dans la porté de la fonction (scope)
Un scope = entre 2 accolades
Dès qu’il y a des accolades, il y a un scope (classe, méthodes, conditions, boucles etc)
Un champs étant déclaré au sein d’une classe, le champs est persistant et est dispo dans
les méthodes

Signature de fonction


--- Fonctions : ---

[Type de retour]  LabelDeLaFonction ()
Fonction retournant un résultat
[Type de retour]  LabelDeLaFonction ( type labelParam1, type labelParam2 etc)
Autant de paramètres que l’on veut. ça va nous créer une variable automatiquement.


--- Procédures : ---

void LabelDeLaFonction()
void LabelDeLaFonction( type labelParam1 etc)
Pas de retour, on peut demander des paramètres (ex: Debug.Log)

Signature : un mode d’emploi
-Permet de savoir ce que l’on va recevoir à la suite d’un appel
-Consultez la doc pour avoir plus d’informations sur les fonctions que vous utilisez

Boucles : while
On refait un ensemble d’opération TANT QUE la condition donné est vrai.
Attention, si cette condition est fausse dès la première fois on saute le bloc
while( CONDITION)
{
Debug.Log(“C’est beau mais c’est loin”);
}

Boucles : do while
Même chose que le while à la seule diﬀérence que l’on évalue la condition à la ﬁn du
bloc de code. On est donc assuré de faire le bloc au moins une fois.
do
{
Debug.Log(“C’est beau mais c’est loin”);
} while( CONDITION);

Boucles : for
Parfois on veut faire une boucle un certain nombre de fois déjà déﬁni à l’avance.
Le for nous permet de rassembler ces instructions en une ligne. Utile pour parcourir un
tableau
for( INIT ; CONDITION ; ITERATION )
{
}

Boucle : foreach
Évolution du for, permet de parcourir de bout en bout une collection (IEnumerable)
public List<string> jours = new List<string>() { “lundi”, “mardi”, … };
Debug.Log(“le facteur n’est pas passé, il ne passera jamais”);
foreach ( string j in jours )
{
Debug.Log(j);
}

Propriétés

Habituellement …
Nos champs sont privés, donc il est de coutume de créer une méthode qui se contente
de nous retourner la valeur d’un champs. De cette manière l’information peut être
disponible.
string _myMessage;
string GetMyMessage() => _myMessage;

C’est la qu’intervient les propriétés
“Syntaxique Sugar” permettant de simpliﬁer l’écriture de ces méthodes basiques
string _myMessage;
public string MyMessage
{
get => _myMessage;
set => _myMessage = value;
}

On peut customiser la visibilité
public string Message
{
get => _message;
private set => _message = value;
}

On peut également omettre le corps du getter et du setter
public int CurrentHealth { get; private set; }
(Ici le compilateur nous crée automatique un champs qu’il utilise dans la propriété)

Résumé
Dès que l’on veut rendre accessible une information au reste du monde, on expose
alors une propriété.
De cette manière, on garde le contrôle sur nos champs. On peut proposer aux autres
composants de changer les valeurs MAIS ils doivent passer par nous (set), ce qui nous
permet de nous assurer qu'on ne nous injecte pas des valeurs bidons.

Visibilité
Pour chaque champs, propriétés et méthodes on peut spéciﬁer un niveau
d’accessibilité. Ce membre ne sera visible que pour une catégorie précise.
private : Disponible que pour la classe elle-même

internal : Disponible qu’au sein de la même DLL (Assembly Deﬁnition sur Unity)
protected : Disponible pour la classe elle-même ainsi que pour les classes enfants

Héritage
Certains composants ont potentiellements des méthodes en commun, des champs en

Au lieu de copier/coller, utilisons l’héritage

virtual, override

base

sealed : fermer l’héritage
